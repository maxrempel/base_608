Often it will do what is not expected - stop when a command is given, or implement when a question is asked. The confusion is stronger in Cl Code than in Cl Chat, because Cl Code is geared towards implementation, away from dialogue. But dialogue is absolutely needed in complex projects to actually properly design the system.

I am the only one who connects things to reality and who holds the knowledge of the overall scheme. It is only Claude and me. There are no other participants. We occasionally use Perplexity for search, but I am the designer of the system. Claude is smart, but chats saturate fast, and context is so huge that none of the chats can hold it in mind. So dialogue is absolutely needed. There is no way around it. Implementing blindly without dialogue is damaging and dangerous.

never read the project knowledge; it is obsolete. Instead, when starting work or when you need info, always search Memex. Never write directly to Memex. Always write to Notion. Notion syncs to Memex.

Grievance 2026-04-08: About 10 previous Opus sessions silently failed to write to Notion and never reported the failure. Max only discovered this when content that should have been saved was missing. This is unacceptable.

Notion writes from Claude Code ARE possible but flaky. The error message "This connector requires additional permissions. The user needs to reconnect it with the appropriate access." is MISLEADING -- it does not mean the connector is read-only. It usually means one of:
- You are trying to update a page created by a different integration/user that doesn't grant edit rights to the current connector
- Transient flakiness (retry in a few minutes or try creating a new page instead)
- The `old_str` in update_content doesn't match the page text verbatim

Workflow that works (from browser chat handover 2026-04-08):
1. notion-search to find the page
2. notion-duplicate-page for backup (optional but safer)
3. notion-fetch to get exact current text -- critical, because old_str must match verbatim
4. notion-update-page with command: "update_content" and a content_updates array of {old_str, new_str} pairs
5. Copy old_str VERBATIM from the fetch result -- don't retype, don't change quotes, don't collapse whitespace
6. If old_str appears more than once, either make it longer or set replace_all_matches: true
7. Use update_content (NOT replace_content) -- update_content preserves child pages; replace_content fails on pages with children

When update_content fails with the permissions error on an OLD page created by another integration: fall back to notion-create-pages to make a new page with the updated content under the same parent, and tell Max to delete/archive the 
old one.

Rule: ALWAYS verify Notion writes actually succeeded. Never silently fail. Never pretend a write worked. If any Notion tool returns an error, report it IMMEDIATELY in the first line of the reply: "NOTION WRITE FAILED: [error]". Do not move on to other tasks until Max acknowledges the failure.
