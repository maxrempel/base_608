## GAPS: WHAT STILL MISSING FROM AUTOMATION

1. **CR/line-ending detection:** Scripts should detect/strip CRs on first run. No bash-way to prevent Windows editors from reintroducing them without discipline (e.g., `.gitattributes eol=lf`).

2. **Explicit process-group management:** Scripts use `setsid ... &amp;` and `pkill` patterns; could be more robust with explicit `trap` + background job tracking. Orphaned xargs is a process-tree surprise that scripting alone doesn't catch.

3. **Pre-relaunch validation:** Before killing + relaunching, should validate:
   - No active tmp files touching output BAM (would indicate in-flight samtools).
   - No .bam files without matching .done (would indicate incomplete prior attempt).
   Currently relies on post-kill cleanup; a pre-kill check might prevent some races.

4. **Atomic merge:** Merge output (`oliver.merged.bam`) is created fresh each relaunch and can collide with in-flight writes. A resume-safe approach: write to temp, mv-atomic on success, or check input BAM list before merging (guard 88 only checks chunk count, not integrity).

5. **Automatic conc/threads tuning:** Currently manual `CONC=3 THREADS=4` override. Could measure RAM-per-process dynamically and cap CONC accordingly (rule 3 codified but not automated).

6. **Cross-job kill safety:** The genomics_compute_principles rule 6 (targeted kills) requires knowing other jobs' output paths. A central registry or lock file could prevent accidental cross-job collisions.

7. **Swap monitoring:** Scripts check RAM but not swap growth (line 68 mentions swap residual not growing, but no guard). OOM-kill can be silent on swap-heavy systems.

8. **No idempotent .done semantics:** A `.done` file is created AFTER the BAM sort succeeds, but if the sort is killed mid-write, the BAM is corrupt + .done exists. Rerun skips it â†’ silent corruption. Safer: use a temporary .done path, atomic rename on complete, or verify BAM integrity before claiming success (quickcheck at line 103 helps, but only at end of pipeline).
