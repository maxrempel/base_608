## DECISIONS + WHY

### The bug
In `C:\claude_base\tools\attention\attention.py`, the alarm **force-unmuted** the speakers every time it fired. Specifically:
- Line 163: `vol.SetMute(0, None)` - explicitly unmutes the AudioEndpoint.
- Line 164: `SetMasterVolumeLevelScalar(...)` - forces volume to 100%.
This was intentional "can't-miss" design but broke the user's ability to silence the alarm by muting the machine.

### The fix (two parts)

**1. New helper function `_device_is_muted(device_name_substring='Realtek')`**
- Uses `pycaw` (Python Core Audio Windows bindings) to query the current mute state via `IAudioEndpointVolume.GetMute()`.
- Takes a substring to match the audio device by friendly name (defaults to `'Realtek'` since that's what Pine has).
- Returns `True`/`False`/`None` (None = couldn't determine). Treats errors and missing devices as "not muted" (fail-safe: if we can't read mute state, we allow sound).

**2. Gate in `main()`**
- Before calling `_audio_alarm(...)`, the script calls `_device_is_muted()` and checks the `--force-voice` flag.
- If `--force-voice` is NOT set AND the device reads as muted ? **skip the audio alarm entirely** (screen-only alert, no sound).
- If `--force-voice` IS set ? bypass the mute check and play audio anyway (emergency override; defaults to off).

The reasoning: mute is the user's explicit signal for silence. The alarm should honor it unless overridden. The screen flash still fires - visual alert remains.

## GOTCHAS / DEAD ENDS RULED OUT
- **Don't just delete the unmute lines** - that would leave the alarm always at 100% volume even when not muted. The proper fix is a conditional gate.
- **`pycaw` must be installed** - it was already available (the import worked during verification).
- **Device name matching is substring-based** - if Pine's audio device changes from "Realtek" to something else, `_device_is_muted()` will return `None` and default to allowing sound (fail-safe). This is acceptable; if it becomes a problem, the substring can be updated or made configurable.
- **This only fixes `attention.py`** - if there are other sound-producing paths in the Claude Code stack, they are untouched and could still blast through mute.
