## GOTCHAS + DEAD ENDS ALREADY RULED OUT

1. **Shell escaping hell over SSH** - `cmd` chaining with `&` and `echo ---` gets mangled across SSH to Windows. Use Python inspection scripts copied via SCP, or PowerShell `-NoProfile -Command` with careful quoting. Direct `ssh ... "python script.py"` works best.

2. **Not a schedules-path mismatch** - E16 checked: both `wakeup.py` and `wake_listener.py` derive their schedule directory from `BCAST_BASE`, which points to `C:\claude_base\branch_bulletin` on both machines. The schedules are being written and read from the same place.

3. **Not a git divergence in wake_listener.py logic** - Centauri is behind but only by 2 lines (cross-machine force-wake fixes). The scheduled-wake code path exists in both. The script-level test hasn't been run on Centauri yet - E16 was about to when Max interrupted.

4. **Cross-machine force-wake DOES work on Centauri** - session m04 confirmed this. That uses the same exit-code-2 mechanism, which means the wake primitive functions. The failure is specific to scheduled/long-term wake, likely because the desktop app doesn't support `asyncRewake` properly.

5. **Centauri has ~10 Claude.exe processes running** - these are the desktop app. They'll need to be killed before the CLI takes over to avoid port/auth conflicts.

6. **Do NOT use `where claude` on Centauri** - it returns nothing useful because the desktop app binary was never added to PATH. The native exe lives at `C:\Users\maxre\AppData\Local\AnthropicClaude\Claude.exe`.
