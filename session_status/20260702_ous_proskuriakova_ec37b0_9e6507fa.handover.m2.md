### DB duplication investigation

**Finding (completed): There is NO real duplication.** I was confused by my own cross-wired lookups.

MOMA has TWO independent counters that happen to overlap numerically from 1-1191:
- `jobs.id` - auto-increment job ID (now ~3089+), any row type
- `legacy_plate_id` - plate-only namespace (now ~1191), only rows with `role='plate'`

Every plate lookup in the entire codebase uses `WHERE role='plate' AND legacy_plate_id=?` - the `role` column IS the "other identifier" Max guessed. p1184-the-plate (Art Nouveau interior, job 3060) and job-1184-the-shot (shuttle exterior) never conflict because no query ever crosses the namespaces.

**Why it only surfaced now:** I looked up bare `id=1184` (got the shot) and separately `legacy_plate_id=1184` (got the plate), saw two different images, and panicked. The system never confuses them. The "917 collisions" were a mirage - same digits, different namespaces.

**Max's verdict:** No renumbering needed. No corruption. System is sound. He may still want the cosmetic `P` prefix rule so future sessions don't repeat my panic.

## GOTCHAS

1. **fire_job requires `conn` as first positional argument.** Easy to forget. Pattern: `fire_job(conn, job_type=..., ...)`.

2. **fire_image uses `ref_bytes_list=` for multiple refs, NOT `ref_bytes=`.** Passing a list to ref_bytes= gives a cryptic type error.

3. **D1Client has `.query_sql()` for SELECT, `.execute_sql()` for writes. `connect_db()` returns a D1ConnectionProxy that only has `.execute()` and `.commit()`.** Don't confuse them.

4. **Do NOT repeat identical inline bash/python one-liners 3+ times** - the suicide-prevention hook blocks them. Write a .py file and run it once instead.

5. **The system auto-shrinks refs before upload** (24.2 MB ? 1.4 MB, ~6%). Large ref sets (10-12 images) take ~50-75 seconds to generate, not the 2+ minutes of the first unshrunk v34. No need to manually downscale.

6. **Soft "inspired by" language works better than rigid "EXACTLY from" for gpt-image-2 with concept strips.** Over-specifying causes composition rigidity (characters facing camera, wrong object counts).

7. **Plate IDs and job IDs are different namespaces.** Don't look up a plate by bare `jobs.id` - always include `role='plate'`. The imager uses `P` prefix for plates (P1184) vs bare numbers for jobs (3087).
