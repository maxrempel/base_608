## DECISIONS + WHY

### Root cause: render() wipes the board BEFORE building rows
`render()` at line 714 did `body.innerHTML = ''` immediately, then called `groupLines()` and iterated rows. If `groupLines()` or any single row threw an exception during a *standalone* render() call (from drop/pin/toggle/undo handlers - none of which wrap render() in try/catch), the board was already blanked and stayed blank. The stat bar ("85 lines, 572 images") froze because it's only updated on successful `loadAll()`, not from standalone render() calls.

This wasn't a server/data bug - `/api/script_lines?scene=11` returned valid data, and a fresh Playwright load rendered 19 rows + 16 pile items perfectly. Max's tab caught a transient inconsistent moment (sibling D-sessions actively writing scene-11 arrangements to D1 at that moment), and `groupLines()` threw. Because the board was already wiped, it stayed blank permanently until a full page reload.

### Fix applied: compute-before-wipe + per-row try/catch
Three edits to `render()` in `storyboard_editor_v2.html`:

1. **Move groupLines() BEFORE body.innerHTML=''** - wrapped in try/catch. If it throws, the last good board stays visible and a toast + stat error message appears loudly. No silent fallback.

2. **Wrap the per-row forEach body in try** - `try {` right after `const items = g.items;`.

3. **Catch per-row failures** - increments `rowFails` counter, logs to console, but continues building remaining rows. After the loop, if `rowFails > 0`, a toast warns the user: "N spot(s) failed to render (see console)". Then `renderPile()` still runs.
