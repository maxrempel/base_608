# HANDOVER: Nextcloud Silent Auto-Update on Pine

## GOAL (in Max's words)

Automate Nextcloud updates so the wizard dialog never pops up again. The in-app updater nags every ~3 weeks with multiple "click, wait, click, wait" buttons. Max wants zero clicks, zero windows, zero interaction - fully autonomous. Pine is off at night, so the trigger should be idle-based (30 minutes of inactivity), not time-based. If a reboot is ever needed, email Max; he'll reboot when convenient.

---

## DECISIONS + WHY

1. **MSI path chosen over .exe `/S` or in-app silent update.** Online research confirmed both the .exe silent flag and in-app auto-update are long-standing bugs on Windows. Nextcloud's own docs recommend the MSI driven by `msiexec` for unattended installs. Pine already had an MSI install (v33.0.6), so no migration needed.

2. **`/quiet` mode, not `/passive`.** First attempt used `/passive` during elevated setup - this showed a blue progress-bar window (no buttons, but still visible). Max said he needs fully silent updates. Switched the worker script to `/quiet` = completely invisible installer, zero window.

3. **30-minute idle trigger, not 3 AM.** Original plan was a daily scheduled time. Max said Pine is powered off at night and it was getting warm - idle trigger means it only installs when the machine has been untouched for 30 minutes. Never during active work, never at night.

4. **Hidden VBS launcher (`run_hidden.vbs`).** Launching `powershell.exe` directly from Task Scheduler causes a split-second console flash even when "hidden" is requested, because powershell.exe is a console subsystem binary. The `.vbs` script with `WindowStyle 0` launches PowerShell invisibly - same trick used by Max's other invisible sessions. No terminal window, nothing flashable.

5. **Highest-privileges scheduled task is the UAC bypass.** The UAC "Do you want to allow this app to make changes?" (the blue/dark permission box) is what normally blocks silent updates. A scheduled task set to "run with highest privileges" pre-elevates - Windows trusts it and never shows the UAC prompt at runtime. The trade-off: registering or modifying such a task itself requires one UAC click during setup. Max approved two: one for initial task creation, one for the idle-trigger + hidden-launcher reconfiguration. None ever again.

6. **Belt + suspenders on disabling the in-app nag.** The cfg file was edited to set `autoUpdateCheck=false` AND the MSI property `SKIPAUTOUPDATE=1` was baked in. The MSI property persists across upgrades; the cfg edit kills the nag immediately. If either ever reverts, the other holds.

7. **mxmail for reboot notification.** The worker script checks the MSI exit code. If it indicates a reboot is needed (exit code 3010), it emails Max via the existing `mxmail` CLI tool. No dialog, no nag - just an email.

## GOTCHAS & DEAD ENDS RULED OUT

1. **`.exe /S` flag is flaky** - multiple online reports confirm it fails. Not used.
2. **In-app silent auto-update is broken** - confirmed via GitHub issues (#7280) and forum threads. Not used.
3. **`/passive` shows a blue progress bar** - tested, rejected. Switched to `/quiet`.
4. **Launching `powershell.exe` directly from Task Scheduler flashes a console window** - even with hidden settings. Solved via VBS wrapper.
5. **Modifying a highest-privileges task requires elevation** - changing the action or trigger needs another UAC click. The setup script (`setup_elevated.ps1`) handles this if the task ever needs reconfiguration.
6. **Nextcloud must be closed during MSI install** - the worker script does this by stopping the `nextcloud.exe` process before calling `msiexec` and relaunching it after.
7. **Some users report "reboot required" nags even with MSI** - the script handles exit code 3010 by emailing Max. Not encountered yet on Pine, but covered.
