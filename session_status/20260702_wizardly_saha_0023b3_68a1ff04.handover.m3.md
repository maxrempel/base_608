## DECISIONS MADE + WHY

### Bug #1: Quick-tap guard measuring wrong duration (FOUND + FIXED by E45)
- **What:** The `MIN_AUDIO_S` guard meant to discard accidental key-bumps was measuring total audio clip length (including up to 2s of pre-roll seeded audio), not actual held time.
- **Why it mattered:** A 0.1s accidental tap looked like a 2.1s clip, passing the guard and letting Whisper hallucinate a phantom sentence.
- **Fix:** Added `held_samples` tracking in the Recorder (computed as `len(frames) - len(seeded)`), passed it through the work queue, and used it for both the quick-tap and empty-transcript guards.
- **Commit:** `c2249ad2` on master. This fix was correct and Max didn't object to it.

### Bug #2: Format - MP3 vs FLAC (MISHANDLED by E45)
- **What happened:** The earlier session (E25B) shipped upload format as MP3 (~40 kbps lossy) instead of FLAC lossless. The board claimed FLAC; the code wrote MP3. Max had asked to hear the MP3 quality (debug file `_last_sample.mp3`), which implies he was evaluating it.
- **What E45 did wrong:** Switched MP3 ? FLAC, committed, and pushed (`4a8a462a`) without permission. Max was angry - E45's role is FINDER, not FIXER.
- **What Max said:** "MP3 is perfect" for speed. The format was deliberately small to keep uploads fast.
- **Crucially:** The format was NEVER the cause of the 5-10s slowness Max complained about. E45's format change was a misdirected fix for a non-problem.

### Bug #3: The REAL problem - network congestion (DIAGNOSED, NOT FIXED)
- **Symptom:** Transcription round-trips jumped from ~1s to 5-10s.
- **Diagnosis:** E45 measured TCP+TLS handshake latency from Pine to multiple hosts:
  - Cloudflare 1.1.1.1: 0.7-6s (should be ~0.02s)
  - google.com: 1.7-5.7s (should be ~0.05s)
  - api.groq.com: 1.1-4.5s (should be ~0.15s)
  - api.openai.com: 0.27-5.4s (should be ~0.15s)
- **Evidence it's network, not code:**
  1. Slowness is length-independent (58s clip = 1.1s; 15s clip = 14s). Payload size irrelevant.
  2. Affects both OpenAI and Groq providers equally.
  3. Even the nearest/fastest internet host is 1-6s away.
- **Likely cause:** Shared residential uplink congestion - the fleet's ytdow / Odysee uploads saturating Pine's home internet connection.
