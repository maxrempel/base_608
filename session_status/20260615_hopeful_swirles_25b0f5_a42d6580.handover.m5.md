## DECISIONS MADE + WHY

### Root Cause Discovery
- **Found:** The router (OpenWRT, 192.168.1.1) had its entire **2.4 GHz radio (radio1) disabled**. The "Rempel" network Max sees on his phone uses only the 5 GHz radio (radio0, channel 149). The Kidde alarm is 2.4 GHz-only hardware - it physically cannot see or join 5 GHz. It saw dozens of neighbors' networks but zero from Max's home because nothing was broadcasting on 2.4 GHz at all.
- **"maxhome"** appears in the alarm's scan list but is **not on Max's router**. It is a neighbor's network or nearby device. Confirmed by checking all active/disabled SSIDs in the router config - none match.

### Network Creation
- Created a temporary SSID **"KiddeSetup"** on the 2.4 GHz radio with password **kidde12345**, WPA2-PSK only, channel 11, 20 MHz width, broadcast enabled.
- **Did NOT touch** the main "Rempel" network or its password (`razdvatri`).
- Turned the 2.4 GHz radio back on (it was disabled in config: `wireless.radio1.disabled='0'`).
- Two old disabled 2.4 GHz SSIDs ("Rempel3 2.5G", "Rempel4 2.4G Bajor") were left alone, still disabled.

### EMF Discussion
- Max worried about "proliferation of networks" causing EMF pollution. Clarified: multiple SSID names on one radio share a single transmitter, same channel, same antenna - extra beacon frames add near-zero EMF. The only meaningful RF change was turning the 2.4 GHz radio back on, which is unavoidable for any 2.4 GHz-only IoT device to function.

### Long-Term Plan (tabled)
- I proposed: after pairing, delete "KiddeSetup" and keep exactly one permanent 2.4 GHz network alongside the 5 GHz "Rempel." Max was considering this when the subscription discovery halted the work.
