## GOTCHAS

- **Checkpoint mismatch was a silent re-run bug.** The original wrote e.g. `extract_done` but checked `extract_done.complete` - meaning every stage would re-execute on every run, since the guard file was never created. Now both write and check `.complete`.

- **v02 audit base may not exist on disk.** The repo has `audit_omon_all_reads_v01.py` only. The script expects `v02` at the `CONTROL_AUDIT_BASE` path. If only `v01` is deployed, the SHA check will fail. This is the single deployment-blocker.

- **Pilot mode deliberately uses a wrong SHA to test rejection.** This means pilot will always "fail" the detection-marker check by design - that's the correct behavior proving fail-closed. The script then writes `PILOT_COMPLETE` (not `RUN_COMPLETE`) and exits 0 only if the rejection worked. If the wrong hash *passes*, it exits nonzero - a real failure.

- **Inline D10 metrics is chr1-22 only.** The old external script (`build_sample_chrom_metrics_v01.py`) included chrX and chrY. The inline replacement deliberately excludes them, matching the Asto wrapper's accepted behavior.

- **No NVMe, no old-worker paths.** The corrected script has none of these legacy references - it was verified clean.
