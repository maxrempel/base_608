## GOAL (Max's own words)

"Index timecodes automatically, by using ds4flash [DeepSeek] to read transcript, search online for the song name, authors, if it is the song authored by the performer, note that, if that song is already in the catalog - combine. Also, i think we need a fuzzy, much of all songs in catalog by full text - that would allow to increase identification a lot, like manyfold. Even with poor transcription quality - full text would match, so we will get tons of songs identified."

The machine auto-indexes timecodes for the missing ~45% of the 1558-video concert catalog, learning from the existing human-curated ~55%. Fuzzy full-text matching (lyrics, not just titles) is the key lever. Humans fill the blanks via a gamified UI for hard cases (face recognition for performer identity).

---

## DECISIONS MADE + WHY

1. **Approach A chosen over B**: Auto-timecode brand-new videos from scratch (learning from human catalog), NOT merely enrich the existing catalog. Rationale: Max said "only 55% is currently indexed" and "learn from the existing human curated catalog. And then start indexing from scratch." The 1049+ unindexed videos are the target.

2. **High precision, no guessing**: Machine labels a segment ONLY when confident - either a full-text lyric match against known songs, or a clear spoken announcement of authorship. Everything else gets a blank label. "A failed-to-identify segment is more precise than a wrong label." Humans check + fill blanks.

3. **Two distinct machine outputs per video**: (a) Segments - where each song starts/ends (timecoding EVERYTHING); (b) Confident labels - the few segments where identification is certain. These are separate concerns; segmentation ? labeling.

4. **Clean split with b6**: b6 (formerly b14, renamed itself) owns the thorough starts+ends segmentation pipeline. b14 (current indexer) builds the labeling layer ON TOP of b6's segment output. No duplication. b14 must never touch app.js (b6's domain).

5. **"Song start" definition**: Right after the last spoken word, musical intro INCLUDED - not the first sung word. That was a live bug b7 is fixing; this spec must be respected.

6. **Language convention**: Unlabeled segments = "failed to identify," never "wrong." Adopted from Max's correction.

7. **Validation proved the bet**: A leave-one-video-out prototype (idx_validate_v01.py, 25 videos / 2172 songs) showed 47% exact-title recurrence across videos and 63% of titles findable directly in the transcript. Combined recall from recurrence + fuzzy + web lyrics is expected much higher.

8. **YouTube harvest paused**: b9 is using the home IP for a 1558-video backup right now. Mass transcript-fetching would clash. No YouTube until b9 coordination. The 452 already-local transcripts are the free offline sandbox.
