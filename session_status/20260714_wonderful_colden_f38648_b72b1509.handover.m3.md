## DECISIONS + WHY

- **Rooms as knock-only, not auto-hear:** Rooms already existed in bcast.py but auto-pushed full message bodies into every member's catchup each turn. That directly contradicted Max's "shouldn't be loaded automatically" requirement. Changed the read-hook so members get a one-line KNOCK ("room 'X': N unread - open with `bcast.py room X --read`") instead of the bodies. The body appears only on explicit `--read`, which advances the cursor to clear the knock. This creates exactly the "knock on the door" resistance Max described - visible, not isolated, but not given by default.

- **moveteam uses explicit member list, not team letter:** Max said "move teams P1, P2, P3." But P1/P2/P3 are projects, not bcast team letters - all the x-sessions (x5, X7A, X12B, X21B, etc.) share team letter `x`. Using `moveteam x` would have dumped all 15 x-sessions into one room. Instead, read the member lists from Max's board screenshot and created three rooms with explicit `--members` lists. This was the right call; Max confirmed by not objecting.

- **Posting barrier is room-membership-gated, not team-gated:** The barrier triggers if `_rooms_of(me)` returns non-empty - i.e., the session is a member of ANY room. If a team has rooms but a particular session hasn't been moved into one, that session posts freely. This matches Max's "if the board has rooms and the members are already in the rooms, then they have to get resistance... if it is just one or two sessions in the board, that's fine."

- **Wake fix - id-keyed lock (beacon) as authoritative source of live session_id:** Root cause diagnosed by inspecting live state: X12B's cwd was `C:\claude_base` (shared main checkout, NOT a worktree), its stamped session_id was dead (listener had re-armed under a new Claude session_id), and the 2026-07-04 worktree-lock recovery only works for sessions in their own worktrees. An undelivered `.signal` file was sitting in `wake/signals/` forever. Fix: the listener now also maintains `wake/locks/id_<bcastid>.lock` (content = current session_id, refreshed every ~5s, dropped on exit with an own-it-to-drop-it guard). In bcast, `_session_id_for` checks this FIRST (with a 30s freshness gate), before falling back to stamped sid or worktree lock. Works for shared-checkout sessions, which were the blind spot.

- **Emoji removal done via Python transform, not Edit tool:** The emoji bytes made exact string matching unreliable with the Edit tool. Wrote a small inline Python script using ASCII anchors to strip the SIG_POOL and rewrite `_signature` to a plain shim returning the id as-is.
