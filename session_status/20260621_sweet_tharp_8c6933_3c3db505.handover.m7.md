## DECISIONS MADE + WHY

**1. Rejected all ready-made tools** - Zemail (unproven, sends all mail to third-party API, Claude Code only), Context Link (no real reviews, wrong shape for 505k emails), ragmail (needed Rust/`just`, not Windows-friendly), Shortwave/Missive/Gmelius (standalone apps, not Claude integration), semantic-mail (72? GitHub tool, pure Python, closest fit - we adopted it but heavily rewrote it).

**2. Chose semantic-mail as the base** - lightweight Python tool by yahorbarkouski on GitHub, Gmail API + ChromaDB. Installed at `C:\Users\maxre\semantic-mail` on Pine (the laptop), then **replaced the entire sync pipeline** because it loaded all 505k emails into memory at once with no checkpoints - would have crashed.

**3. Built custom month-by-month, resumable pipeline** - `full_archive_driver.py` + `archive_index.py` index most-recent-first, commit each month durably, resume safely after crash/sleep. Each email's full `.eml` + attachments are saved, PDF/DOCX text is extracted and embedded, images saved unindexed.

**4. Index lives in Cloudflare Vectorize (NOT local)** - created index `max-emails` (1536-dim, cosine) in the same Cloudflare account as Memex (`e4dc2224...`) but **completely separate index** - Memex has `claude-memory` and `babel` (768-dim); Gmail never touches them. This makes search reachable from anywhere (web, Android, Claude Code).

**5. Archive lives on teal16 (Centauri D:, 12.9TB free)** - `.eml` files + all attachments saved there, organized by month. Pine only stages one month then SCPs it to teal16 and removes local copy, so Pine's ~13GB free is never threatened.

**6. Pipeline migrated from Pine (laptop) to asto (AstolfoDebian, always-on)** - Pine sleeps, which kept pausing the indexing for hours. asto (Liz's old PC, Debian, 985GB free, always-on) won't sleep. Nothing permanent lives on asto - it stages one month, ships to teal16, cleans up (respects the guest rule).

**7. asto required `loginctl enable-linger`** - without it, systemd killed the container + driver every time my SSH session ended. Enabled now; processes persist across sessions.

**8. Installed a watchdog cron on asto** - relaunches the driver on reboot and every 15 min if it's not running. Uses `setsid` (not `nohup`) to truly detach inside distrobox.

**9. Built Cloudflare Worker for Android access** - deployed at `gmail-mcp-search.max-rempel2.workers.dev`, exposes a `search_gmail` tool via remote MCP. Uses the OpenAI embedding key to embed the user's query, queries the Cloudflare Vectorize `max-emails` index, returns results with teal16 archive paths. The URL is: `https://gmail-mcp-search.max-rempel2.workers.dev/mcp/Beyfo7uPMsE7yGuyIWCsbNfPZ_4uz-ho`

**10. E11 built the `semanticgmail` Claude Code skill** - wraps `search_cf.py` for laptop use. E10 (me) handles the engine, E11 did the user-facing skill.

**11. Fixed a long-email bug** in semantic-mail's OpenAI embedder - emails >8192 tokens silently killed entire batches. Patched to truncate per-email with tiktoken and fall back to per-item on batch failure.

**12. Added a duplicate-message rule to global2** - "duplicated messages are a bug in the Claude Code app and should be treated as such." If the same message appears verbatim, recognize it as a duplicate and don't re-do the work.

## GOTCHAS + DEAD ENDS

**Fixed bugs:**
- **Long emails killed batches** - patched `openai_embedder.py` to truncate >8192-token emails with tiktoken
- **Pine only 13GB free** - `full_archive_driver.py` has a disk guard, but the real fix was moving the pipeline to asto + teal16
- **Body-only index on Pine** superseded and stopped - was filling Pine's disk
- **Backup JSONL clobbered on teal16** - `_vectors` was a file not a directory; fixed by creating it as a dir, driver now ensures remote dirs exist
- **asto killed processes on SSH logout** - `Linger=no`; fixed with `loginctl enable-linger rempel`
- **`nohup` didn't detach inside distrobox** - replaced with `setsid` in the watchdog
- **False PID matches in monitoring** - `pgrep -cf` was matching my own command string; now use Cloudflare vector count as the reliable signal
- **Worklog `cd` bug** - same root cause as bcast: worklog keys by cwd, so `cd` into repo splits logs across files. Reported to C6.

**Dead ends ruled out:**
- Zemail, ragmail, Context Link, Shortwave, Missive, Gmelius, PocketLLM, GBrain, RetrieveIT - none solve "Claude searches my Gmail on Android"
- Gmail's native Claude connector - keyword-only, not semantic
- IMAP password auth - Google killed it May 2025; OAuth is the only sanctioned path
- Running on Pine only - laptop sleeps, blocking a multi-day job
- Memex merging - Max explicitly wants Gmail separate to avoid junk contamination

**Design invariants (don't change):**
- Gmail index is `max-emails` (1536-dim), completely separate from Memex's `claude-memory`/`babel` (768-dim)
- Pipeline is read-only Gmail scope ? Google cannot close the account for this
