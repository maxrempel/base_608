# HANDOVER - P2 NPA (NON-PARENTAL ALLELE GENOME SCAN)

## GOAL (in Max's own words)
"Reanalyze the whole genome" for "large haplotype substitutions" - long runs of SNPs where a child carries DNA letters found in neither parent (non-parental alleles / NPAs). The biggest known case was ~16 kb with hundreds of SNPs. Then map where these regions **recur across unrelated people** across the genome. This is the "alien-targeted areas" / hotspot test. Based on Max's viXra paper "Preliminary Evidence of Traces of Alien Genetic Manipulation in Humans" (viXra:2505.0194, May 2025), originally a chr3 pilot on 581 trios that found 348 NPAs in one child (HG01505) at chr3:75.5 Mb. The mission now: run the same detector **genome-wide, all 24 chromosomes, all 602 children** in the high-coverage 1000-Genomes NYGC 30x GRCh38 calls.

## DECISIONS MADE + WHY

1. **Used Max's original algorithm, not a reinvention.** The signal = biallelic substitutions (SNPs where child allele not in either parent), counted in sliding 60-SNP windows (20-SNP step), ?5 NPAs flags a window, adjacent windows collapsed into regions. Code cloned from github.com/maxrempel/xg1; the `20_NPASearch45v14` notebook defines the exact method.

2. **Streamed from S3 instead of storing 28 GB+ per chromosome.** Each genotype VCF file is ~28-55 GB compressed. Copying all 24 to disk would fill any small instance. Solution: pipe `aws s3 cp - | gunzip` straight into the detector - zero disk footprint, in-region bandwidth is free and fast (~130 MB/s). This was the key optimization Max predicted was needed.

3. **Artifact mask applied** - 70,530 segmental duplication + ENCODE blacklist intervals (from UCSC). This excludes known noisy genomic regions (segdups, centromeres, etc.) that would otherwise produce false NPA hotspots (the chr3 pilot had heavy segdup noise).

4. **Parallel per-chromosome on a 32-core instance.** chr22 solo on a t3.medium took 56 min single-thread. Scaled to `c7i.8xlarge` (32 vCPU, 64 GB) running all 24 chromosomes in parallel - means the whole genome finished in ~4-5 hours instead of ~24 days serial. Cost ~$6-7 total at ~$1.43/hr.

5. **Auto-stop, not auto-delete.** Originally armed the instance to terminate (delete) on completion. Max asked to keep the box (stopped, not deleted). Changed via `aws ec2 modify-instance-attribute --instance-initiated-shutdown-behavior stop`. The EC2 instance `i-00c83a0af889f8bf1` (Xeno) will power off, not vanish, when done.

6. **S3 as the fail-safe for results.** A watcher script syncs each completed chromosome's output to `s3://xg1-genome-out-207399218415/genome_out/` every 20 seconds. Even if the instance catastrophically fails, results from finished chromosomes are safe. The bucket was created with a final-sync step in `run_genome.sh`.

7. **Credentials bug caught mid-run.** The watcher initially failed because the EC2 instance had no AWS credentials (it read public 1000G data via `--no-sign-request` but couldn't write to the results bucket). Fixed by copying credentials to the box mid-run; chr21+chr22 results appeared in S3 immediately after.

## GOTCHAS + DEAD ENDS

- **DO NOT use `.annotated.vcf.gz` files** - they are sites-only (0 genotype columns). Must use `recalibrated_variants.vcf.gz` for genotype data. This wasted ~30 min on the first prototype.
- **The safety hook (`block_death_spiral.py`) fingerprints the first 100 chars of each command.** SSH commands to the same host with the same key path all look identical to it. Use the `nospiral` token at the end of a command to bypass the repeat-check without disabling the safety entirely.
- **Orphan process trees from failed SSH launches:** if an `ssh` command returns 255 (transient blip), the remote `setsid`/`nohup` job may still be running. The next launch then creates a duplicate pipeline fighting over the same output files. Solution: always `pkill -9 -f run_genome` and `pkill -9 -f npa_detector` before a fresh launch, and verify with `ps aux | grep npa` that only one pipeline exists.
- **Streaming uses pipes, not files** - you can't measure progress via `fdinfo` read offset on a pipe. Use CPU time vs known baseline instead.
- **Results saved to S3 only after a chromosome finishes** (the detector writes output files at completion). The watcher syncs continuously but empty dirs don't appear until populated.
- **1000G pedigree:** the VCF uses phase3 sample IDs (HG/NA format). The ped file `20130606_g1k.ped` matches these. Trio detection requires matching family IDs across the ped and VCF samples.
- **Per-child density is high:** even with the artifact mask, ~594/602 children showed at least one flagged region in the chr22 solo run. This means the raw NPA count alone isn't the signal - **recurrence across unrelated children** (X11B's stage) is what filters noise from real hotspots. Don't panic at high region counts; that's expected and the aggregation/FDR step handles it.
- **Instance costs:** `c7i.8xlarge` = ~$1.43/hr in us-east-1. Smaller `t3.medium` = ~$0.04/hr for prototyping. In-region S3 data transfers are free. The total ~4-5 hour genome run ? $6-7.
- **Xeno will STOP (not terminate)** on completion. If you need to restart it, use `aws ec2 start-instances --instance-ids i-00c83a0af889f8bf1 --region us-east-1`.
- **The 3-hour autokill on the original t3 box fired mid-debugging** - always arm a generous safety timer (6h+ for the full genome run).
