## DECISIONS MADE + WHY

1. **Google Docs API batchUpdate instead of browser Find & Replace.**  
   - Reason: browser Find & Replace changes visible URL text but leaves the underlying hyperlink pointing at the old burned meeting. `batchUpdate` can both replace text AND update the hyperlink target. This is now a **LOAD-BEARING WARNING** in the skill and global2 - never use find-and-replace on the mailing doc.

2. **Substring matching on paragraph combined text instead of run-level matching.**  
   - Reason: Google unpredictably splits paragraphs into multiple `textRun` elements. Matching against the concatenated text of the whole paragraph gives stable character indexes that align with the document's own indexes. The script scans for known patterns (date regex, heading regex, etc.) and stores the absolute start/end.

3. **Descending-order edits in a single batchUpdate call.**  
   - Reason: delete+insert requests are emitted back-to-front so earlier character indexes remain valid after each edit.

4. **Raw REST requests, no google-api-python-client.**  
   - Reason: the heavy Google client libraries are not installed in Pine's default Python, and we want the script to run from any session without extra pip installs.

5. **Telethon user API (Route B) instead of BotFather bot for Telegram posting.**  
   - Reason: an authenticated Telethon session already exists (the `tg_alerts` tool). No BotFather or channel-admin steps needed. Posts appear as the channel itself (as Max's hand-written posts always did). The probe confirmed the channel resolves as `-1004420079347` and Max is creator.

6. **Ban-safety design: single destination, one message per run, repost guard, dry by default.**  
   - Reason: Max explicitly said "Make sure we don't get banned from Telegram." The script only posts to the hard-coded channel, never joins/invites/DMs, refuses to post within 20 hours of the last post (with `--force` override), and does nothing without `--send`.

7. **Trigger word "zoomweek" wired for reusability.**  
   - Reason: Max asked "how do we make it reusable by other sessions?" The standard path is: tool + README in `claude_base/tools`, commit+push, `_tomemex` suffix for Memex, a pointer block in auto-loaded `global2.md`. The global2 pointer (and the skill) make any session know about the tool before it thinks to search.

8. **OAuth for Docs: reused existing installed-app client.**  
   - Reason: a client existed (`google_contacts_oauth_20260522.json`, project `stalwart-coast-240620`), we only needed a new refresh token with the `documents` scope. A one-time loopback consent flow was driven in Max's own Chrome. The new token lives in `google_docs_oauth_20260726.json`.

9. **All rotation links + passcode stored in a JSON file.**  
   - Reason: the updater and the Telegram poster both reference the same `rotation_links_v01.json`, ensuring one source of truth.
