### GOAL (Max's words)
- Add a third layer below the global board and team boards: **chat rooms**.
- Rooms are for a smaller subset of the project to have a *private* chat.
- Rooms **must NOT be loaded automatically** - no content in the default feed.
- However, rooms are **not completely isolated** - board members should see that the room exists and that something is happening.
- To actually read room content, a session must **explicitly "knock" / open the door**, i.e. request it with some resistance.
- The user called this "three layers": global ? board ? **chat room**.

---

### DECISIONS MADE & WHY

1. **Didn't build from scratch - modified the existing `room`/`rooms` features.**  
   The `bcast.py` tool already had `room create/join/post` commands and an auto?hear mechanism. But that mechanism was pushing *full message bodies* into every member's context every turn - which directly contradicted the "not loaded automatically" requirement. The code was otherwise sound, so fixing the auto?hear was faster and safer than rewriting.

2. **Changed auto?hear from full?body dump to a one?line "knock".**  
   Every turn, if a room has unseen messages for a member, the session now receives:  
   `room <name>: X unread - open with --read`  
   This satisfies "not completely isolated" (they know something is there) while providing "resistance" (they must take an explicit action to see it).

3. **Knock shows unread *count* only (not sender name or text).**  
   The reasoning was that a count is the simplest "resistance" - minimal info leakage, and the user must actually run `--read` to engage. The assistant flagged this as a design choice, open to change.

4. **The knock persists across turns until the user reads.**  
   Once the user runs `--read` (the door?open), the knock disappears from future turns. If a new message is posted later, the knock reappears with an updated count. This gives a persistent notification without filling context.

5. **Non?members get *nothing* from the room (no knock, no leak).**  
   Only members who joined the room see the knock. But there is no joining approval - in principle anyone *could* knock, so the room is transparent, not secret. That matches the user's "can override" but with resistance.

6. **Tested with temporary `BCAST_BASE` directory - never touched the live board.**  
   Verified: knock appears and counts correctly, clears after read, reappears after new post, self?post does not knock self, non?members see nothing.

7. **Merged and pushed to master immediately.**  
   The feature was clean, tests passed, and other active sessions could benefit from the new behavior on `git pull`.
