## GOAL (in Max's own words)
"I need Claude to find things semantically in my Gmail" - across Claude Code, web, and Android app. Archive everything, index attachments (PDFs, DOCX - images saved but unindexed), keep it separate from Memex, and make it self-sustaining.

---

## DECISIONS + WHY

**Tool choice: semantic-mail (yahorbarkouski), not ragmail/Zemail/Context Link**
- ragmail needed Rust + `just` + ~25h local ingest, rough on Windows
- Zemail was local Claude Code plugin only, unproven, sent email text to a startup API
- Context Link was a one-person $9/mo SaaS with zero reviews, wrong shape (docs, not mailboxes)
- semantic-mail: pure Python, Windows-friendly, swappable embedding providers, OAuth-native
- Used our existing Google OAuth client (`zSyncMain/ssh/google_contacts_oauth_20260522.json`, project `stalwart-coast-240620`) - read-only scope, account-safe

**Embeddings: OpenAI text-embedding-3-small (1536-dim), not Ollama**
- Privacy wasn't a concern (Max: "fuck privacy, only care that Google doesn't close my account")
- OpenAI is fast, cheap (~a few dollars for the whole mailbox), and 1536-dim fits Cloudflare Vectorize

**Index location: Cloudflare Vectorize, not local ChromaDB**
- Max said "keep the index next to memex, in Cloudflare - no point of making it local"
- Created `max-emails` index (1536-dim, cosine) in same CF account as Memex's `claude-memory` and `babel`
- This also enables the Android Worker route

**Archive location: teal16 (Centauri D:, 12.9TB free), not Pine**
- Half a million emails with attachments = potentially hundreds of GB - Pine C: only had ~13GB free
- Pine stages one month ? moves to teal16 via SCP ? deletes local. Disk guard prevents Pine from filling.

**Runner: asto (AstolfoDebian), not Pine**
- Pine is a laptop that sleeps - the run kept pausing for hours
- asto is always-on, 985 GB free, strong CPU/RAM
- Guest rule respected: nothing permanent lives on asto (stages one month, ships to teal16, deletes)

**Linger fix on asto: the key enabler**
- The run kept dying silently. Root cause: `loginctl enable-linger` was off - systemd killed the container + driver every time the SSH session ended.
- Fixed with `loginctl enable-linger rempel` + switching from `nohup` to `setsid` for process detachment
- Added a watchdog cron (every 15 min during backfill, now removed since backfill is done)

**Chunked, resumable design over naive all-at-once**
- The original smail `sync` loaded all 505k emails into memory at once - would OOM, had no checkpoints
- Built monthly chunks processed most-recent-first, each month committed durably before the next
- Idempotent (emails keyed by Gmail message ID) - safe to resume after any crash

**Separate from Memex**
- Max: "memex is already full. Gmail will overwhelm it with junk"
- `max-emails` is its own Vectorize index - never touches Memex's data

**Android via remote MCP Worker, not local tool**
- Anthropic remote MCP connectors sync from web ? Android app automatically
- Built a Cloudflare Worker bound to the `max-emails` Vectorize index
- One-time URL paste into claude.ai ? Settings ? Connectors enables it everywhere

**PDF/DOCX attachment indexing**
- Extended the pipeline: fetch raw `.eml` ? parse MIME ? extract PDF (pypdf) and DOCX (python-docx) text ? embed alongside the email body

**Long-email truncation bug fix**
- Original embedder sent all emails in a batch to OpenAI at once; one >8192-token email killed the entire batch
- Patched with tiktoken: truncate each email to 8000 tokens before embedding, fall back to per-item on batch failure

## GOTCHAS & DEAD ENDS

**Already ruled out:**
- **Zemail**: Claude Code local plugin only, no Android/web path. Unproven, sends email text to a startup API.
- **Context Link**: One-person SaaS, zero reviews, wrong shape (designed for sharing docs/sites, not indexing 500k emails).
- **ragmail**: Good tool by a respected dev, but Rust + complex deps, Windows-hostile.
- **Shortwave/Missive/Gmelius**: Standalone email apps - useless for "Claude searches my Gmail."
- **Claude's native Gmail connector**: Keyword search only, not semantic.
- **RetrieveIT**: Enterprise SaaS, per-seat pricing, your mail on their servers.

**Pitfalls we hit and fixed:**
- **Long emails silently killed batches**: OpenAI's 8192-token limit - one long email made the whole batch fail. Fixed with tiktoken truncation.
- **Naive sync loads everything into memory**: Original tool had no checkpoints. Built monthly chunked driver.
- **Pine disk would fill**: Only 13GB free for 500k-emails-with-attachments. Fixed with stage-on-Pine ? move-to-teal16 ? delete pattern + disk guard.
- **Pine sleep killed the run**: Laptop sleeping = pipeline paused for hours. Migrated to always-on asto.
- **asto `Linger=no` killed processes on SSH logout**: The container + driver died every time the SSH session ended. Fixed with `loginctl enable-linger` + `setsid`.
- **Old PID monitoring was false-positive**: `pgrep -cf` was matching my own SSH command string, reporting "alive" when it was dead. Switched to Cloudflare vector-count delta monitoring.
- **Backup JSONL clobber**: scp treated `_vectors` destination as a file, not a directory - each month overwrote the previous. Fixed by pre-creating the directory on teal16.
- **Global2 duplicate-message rule added** (per Max): Repeated messages from the Claude Code app are a known bug - treat as duplicates, don't re-execute the work.

**Design constraints to preserve:**
- Never mix Gmail data into Memex's indexes (separate `max-emails` index)
- Never let Pine C: run below ~5GB free (disk guard in driver)
- asto is guest compute (Liz's PC) - hold nothing permanent there
- OAuth is read-only (`gmail.readonly` scope) - can't send/delete, account-safe
