## DECISIONS + WHY

### Decision 1: New constant DS_MODEL instead of inlining the string
- Both the health-poker ping and the main `_deepseek_call` had hardcoded `"model":"deepseek-chat"` at two different indent depths.
- Introduced a single `DS_MODEL = "deepseek-v4-flash"` constant near the top, referenced in both places.
- **Why:** DeepSeek retired `deepseek-chat`. Only `deepseek-v4-flash` and `deepseek-v4-pro` are accepted. A single constant means the next model swap is a one-line change.

### Decision 2: Raise all max_tokens budgets significantly
- The new v4 models are REASONING models - they spend tokens thinking ("reasoning_content") before answering. Those reasoning tokens count against max_tokens.
- A tight budget would leave zero tokens for the actual answer, producing empty content with `finish_reason: "length"`.
- Raised: health-poker ping 4?64, short summary 500?2000, two long summaries 1500?4000 and 2200?5000, followup 900?3000.
- **Why:** On a reasoning model, a small max_tokens doesn't truncate the answer - it *deletes* it.

### Decision 3: Empty-content guard instead of bare `.strip()`
- The old code was `return _data["choices"][0]["message"]["content"].strip()`. If content was None or empty, it would raise AttributeError.
- Replaced with a block that checks for empty content, calls `_ds_mark_unhealthy("empty content...")` and raises `DeepSeekUnhealthy`.
- Used the live file's existing `_data` variable (not `r.json()`) so the preceding `_report_spend` ledger call at line 806 stays intact.
- **Why:** Routes the failure into the existing health-poker retry machinery instead of crashing or pushing a blank summary to Telegram.

### Decision 4: Background the ENTIRE /share pipeline, not just ingest
- The old `/share` handler called `fetch_transcript(...)` (yt-dlp caption download) *inline* before returning any response. That blocking call was 2-3 seconds, and it's what Max perceived as "flashing."
- The fix moves the whole pipeline - fetch, Babel ingest, DeepSeek summary, FishAudio MP3, Telegram push - into `BG_EXECUTOR.submit(_bg_share_pipeline, ...)`. The handler just parses the URL and returns.
- Also: every error branch now sends a Telegram message instead of rendering `SHARE_RESULT_HTML`. No lingering error page in any case.
- **Why:** The phone gets its green flash in ~2 milliseconds and auto-closes in 300ms. All the real work (up to 41 seconds for a cold video) happens after.

### Decision 5: Never deploy from claude_base without checking Lak's live version first
- The `C:\claude_base` copy was v0.14.0 while Lak was running v0.17.1.
- Three versions of live work (spend ledger, upload_date fix, Russian prompt branch) would have been wiped.
- **Rule now documented: ALWAYS read the deployment target's VERSION before editing any local "source/backup" copy.**
