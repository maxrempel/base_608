## DECISIONS MADE + WHY

**Root cause found after deep investigation across three domains (client, server, data):**

Five named scenes (lesson1, Tape 1, nadali, media_kit, essay_nonhier) all shared `scenes.rank = 0` in Cloudflare D1. The storyboard client code at line 1286 of `storyboard_editor_v2.html` used:
```
const newScene = d.scene_rank ? +d.scene_rank : ST.sceneRank;
```
Since 0 is falsy in JavaScript, selecting any of those scenes silently kept the previous `ST.sceneRank` (default 10), and every `?scene=` API call continued fetching the old scene's data. This is exactly why two prior Claude sessions (commits 67ad744, b809295, 9f312e6, debff64, b9c5aa3, 59fa6a8) failed - they all tightened numeric scene scoping but never addressed rank-0 / named scenes.

**Chosen fix (option a): Assign unique non-zero ranks to the five rank-0 scenes in D1.**
- essay_nonhier (id 6) -> 301
- media_kit (id 8) -> 302
- nadali (id 9) -> 303
- 'Tape 1' (id 10) -> 304
- lesson1 (id 11) -> 305

Why this approach:
- No existing data references rank 0 (no script_lines, pool_order, spot_order, or spine2_detached rows for any rank-0 scene), so nothing was orphaned.
- `arrangements.scene_id` is an integer FK to `scenes.id` (NOT rank), so arrangement 42 (lesson1) stayed correctly attached.
- `app_state.py` line 33 uses `scene_rank: 0` as the sentinel for the "All" pseudo-selection, so rank 0 must mean only "All" - real scenes had to move off it.
- `arrangement_picker.js` already documented the D41B precedent: "key a scene selection by its UNIQUE scene_id, not scene_rank ... scene_id is unique, so no flip."
- The picker sources `scene_rank` from `s.rank` directly (app_state.py lines 35/67, combo_gui.py line 1659), so the D1 change propagated with zero picker code changes.

**Paired code fixes (three edits, all committed and pushed):**

1. `storyboard_editor_v2.html` - replaced the silent fallback with a loud guard:
   - Old: `const newScene = d.scene_rank ? +d.scene_rank : ST.sceneRank;`
   - New: checks for undefined/null/empty string first, logs and toasts if absent, then `const newScene = +d.scene_rank;` (accepts 0 for "All").
   - Version bumped to `v2.62 | D77`.

2. `slideshow_server_v01.py` - `_scene_arg` no longer silently falls back to scene 10:
   - Old: swallowed bad `?scene=` values and returned `DEFAULT_SCENE` (10).
   - New: absent param still returns 10; present-but-unparseable raises `BadRequest` -> HTTP 400.

3. `slideshow_server_v01.py` - `do_GET` and `do_POST` split into thin wrappers that catch `BadRequest` and call `self.send_error(400, ...)`, replacing the old behaviour of dropping the connection with a traceback.
