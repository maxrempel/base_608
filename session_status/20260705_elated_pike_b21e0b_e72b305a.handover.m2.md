## WHAT WAS FOUND (Root Cause)

**Bitwarden disappeared because multiple Claude sessions collided over one shared browser profile.**

- Bitwarden (logged in) lives inside ONE persistent profile: `C:\claude_base\playwright_profile\`
- Every Claude session runs its own Playwright MCP server, and they ALL point at that same single profile via `--user-data-dir`
- A Chromium profile allows only ONE browser at a time. When a second session tries to grab it, it gets: *"Browser is already in use for playwright_profile"*
- The system's fallback (`--isolated`) spins up a throwaway empty profile with **no extensions** ? "Bitwarden is gone"
- At the time of investigation, ~10 stale Playwright node servers were alive from previous sessions, and a stale `lockfile` (from 12:32 that day) was wedging the profile even though no real Chromium window was open

**Config, extension files, and login data were all intact - nothing was deleted or corrupted.**

## WHAT WAS BUILT (The Fix)

**A Python shim launcher: `C:\claude_base\tools\playwright_bitwarden\pw_mcp_launch.py`**

It sits BETWEEN Claude's MCP config and the real `npx @playwright/mcp@latest` command. At every launch it:

1. Checks whether the shared persistent profile is free (file-lock mechanism)
2. **If free** ? uses the shared profile (`--user-data-dir=playwright_profile`) ? **logged-in Bitwarden** (Max's session)
3. **If busy** ? creates an isolated temp profile BUT **still loads the Bitwarden extension via `--load-extension`** ? Bitwarden is present, just unlogged (other sessions)
4. **Auto-clears stale locks** when no real Chromium process is actually running (prevents deadlock)
5. Passes stdio transparently through to the real Playwright MCP server (Claude talks to it normally)

**All 261 Playwright entries in `C:\Users\maxre\.claude.json` were rewritten** to invoke the shim instead of `npx` directly:

- Every per-project entry with Playwright ? same rewrite
- Backup saved: `C:\Users\maxre\.claude.json.bak_pwshim_<timestamp>`

**The shim was tested end-to-end:**

## GOTCHAS & DEAD ENDS

- **Do not remove or rename the extension folder** - the extension ID (`nngceckbapebfimnlniiiahkandclblb`) depends on its exact path. Moving it changes the ID and orphan the stored login.
- **Do not delete the persistent profile** - Bitwarden's login data lives there. The shim's fallback creates TEMP profiles for busy sessions; the shared profile is only used when owned.
- **Stale lockfiles** from pre-shim sessions will self-heal after restart (shim checks if a Chromium process actually holds the profile before honoring the lock).
- **MCP version drift (`@latest`)** is not a problem because `pw_mcp_config.json` hard-pins `executablePath` to chromium-1224, overriding whatever version the latest MCP expects.
- **The shim uses file-based locking (`msvcrt` on Windows, `fcntl` on Linux)** - tested and working for the lock/unlock/contention paths.
- **~10 old node servers** were running at time of fix. These will die on restart and the shim takes over.
