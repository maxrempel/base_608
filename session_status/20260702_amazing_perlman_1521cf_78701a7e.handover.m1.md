## DECISIONS + WHY

1. **Jump/glitch fix: closed GOP + zero B-frames**
   - Cause: The dense-keyframe masters (0.5s keyframe interval) still had `has_b_frames=2` and open GOP. Stream-copy cutting caused frames near cuts to reference deleted frames, producing visible jumps every few seconds.
   - Fix: Rebuild masters with `-bf 0 -g 15 -keyint_min 15 -force_key_frames "expr:gte(t,n_forced*0.5)" -x264opts "open-gop=0:scenecut=0"`. This makes every 0.5s keyframe a clean, self-contained IDR frame, so stream-copy cuts are seamless.
   - Proven by `prove_cut_fix.py` on a 95s test clip. Max confirmed the video joins are clean (no jumps).

2. **Stabilization method: ffmpeg vidstab (two-pass)**
   - Since the background is stable, a simple `vidstabdetect` pass to generate a transform file, then `vidstabtransform` to apply it, is enough.
   - The proof will run on a 75s clip from the RAW part2 source, encoding directly with the same closed-GOP/no-B-frame parameters that the final master will use, so the stabilized proof is representative.
   - CPU cap: 16 logical cores, so `-threads 8` (~50%) as Max requested.
   - The detect pass also runs multi-threaded (ffmpeg's default for vidstabdetect uses all threads; no easy thread limit on that filter, but the encode pass is capped).

3. **Path issue with Windows drive letter**
   - First attempt passed the full absolute path for the `.trf` file (e.g., `C:/Users/...`). ffmpeg's filter parser interprets the colon as a filter graph separator, causing error: `Invalid argument`.
   - Fix: Run the ffmpeg command from the output directory and use only the bare filename (`stabilize.trf`). Script edited to `os.chdir` into the output dir before running ffmpeg.

4. **Workflow order (hold final assembly)**
   - Max explicitly said: "don't do the final assembly before we fix the audio we're almost done with audio modification principle". So the end-to-end assembly, including cutting with `kf_cut`, must wait until the gated/mixed audio tracks are finalized.
   - Stabilization will produce new master video files that incorporate both the jump fix and the stabilization, but they will **not** be cut or muxed with audio yet.

5. **Proof clips always required before full encode**
   - Because the full masters are large (part1 ~85min, part2 ~85min, raw ~60GB each), a small test clip is used to validate every step before committing to long encodes.
