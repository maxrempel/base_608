---

## GOAL (in Max's words)

Build a system that **automatically indexes timecodes** for concert videos on tamza.com's "kartoteka" song catalog. The machine should:

1. **Time-code EVERY song boundary** (start and end) in every video - even songs it can't identify.
2. **Put a name on a song ONLY when certain** - either by full-text lyric match against known songs, or by a clearly announced authorship in the transcript.
3. **Leave everything else blank** for the human timecoder team to fill via a game-like UI.
4. Use the existing ~26k human-curated song catalog as the matching corpus. "Learn from the existing human curated catalog. And then start indexing from scratch."
5. Pull full lyric texts from the web to massively boost identification - "poor transcription quality might not allow identifying the performer's name, but full text would match."
6. Flag self-authored songs (unannounced + not-in-corpus).

**The human team checks and fills the blanks. No guessing by the machine. An honest blank beats a wrong label.**

---

## DECISIONS + WHY

### Scope split
- **Segmentation (starts & ends)** and **labeling (song identity)** are both mine now. B6 owns an existing pipeline but it only refines human-provided starts - it cannot do from-scratch boundary discovery on unindexed videos. So the whole from-scratch pipeline is B14/B15's job.
- B6 is "old and feeble" - Max said "don't load more work on it."

### High precision, no guessing
- Machine outputs TWO things per video: (a) segment boundaries for everything, (b) confident labels only when certain. Everything nameless goes to the human game.
- "Failed to identify" is the precise term Max wants - not "wrong."

### Validation-first approach
- Before building, I validated the core bet offline on 452 existing transcripts. Leave-one-video-out test: can we identify a video's songs using only OTHER videos' curated titles?
  - **53% recurring** (fuzzy title match) - confirms Max's 50-70% bet.
  - **63% findable in transcript** (title appears in announcement or sung refrain).
  - **36% auto-labelable** (both signals = machine-confident). This is a **floor** - lyric matching + announce-detection will lift it.

### Build order established
1. **COLLECT + MERGE** full texts from the 452 transcripts we already have into one searchable index. Offline, safe, no network spend.
2. **MATCH** transcripts against that index (fuzzy full-text).
3. **SEGMENT** from scratch (boundary detection with no human starts).
4. Later: mass YouTube harvest and web-lyric pulling (require b9-coordination for shared IP; max said b9 is "using the home IP right now" for a 1558-video backup).

### Language convention
- Use "**failed**" not "wrong" for unidentified segments. Max corrected this explicitly.

### Manager role
- When Max started a fresh B15 session to do the actual build, my role shifted to **manager** - watching B15 work from the bird's-eye view, steering it away from net/spend/shared-file collisions, but not micromanaging the build.
