### 2. Model downgrade root cause identified
- There's a mode called **"opusplan"** that deliberately uses Opus for planning then silently drops to **Sonnet** for execution. This is the likely culprit for silent downgrades.
- The fix: run plain **Opus 4.8**, never opusplan.

### 3. Safeguard built - two-part solution
**Part A: Pin Opus as default (prevention)**
- Edited `C:\Users\maxre\.settings.json` to set the permanent model default to Opus 4.8.
- This ensures every new session starts on Opus. Takes effect on next new session + app restart.
- **Why:** prevents most downgrades from ever happening in the first place.

**Part B: Vocalize alarm on downgrade (detection + screaming)**
- Modified `C:/claude_base/compaction_kb/scripts/ctx_gauge.py` to add a model watchdog.
- The watchdog checks the live model on each tick. If the model changes from Opus to anything else, it fires `attention.py` - the same tool Max already uses for alerts.
- **What the alarm does:** throws a **big amber/yellow window across every monitor**, speaks "MODEL DOWNGRADE - type slash model opus to fix it" **out loud 3 times at full volume**, and **stays on screen until clicked away**.
- **Why yellow/amber:** Max specifically asked for orange/yellow flashing window. Amber is the default color in attention.py.
- **Why not auto-restore:** no background tool can type `/model opus` mid-conversation - only the user can. So design is: prevent what we can (pin Opus), scream loudly about the rest (yellow window + voice).
