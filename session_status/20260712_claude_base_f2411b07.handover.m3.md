## DECISIONS + WHY

1. **Abandon single-profile lock** - The old design gave the first session the real profile and all others `--isolated` (empty, logged-out). That's why all parallel sessions kept opening without Bitwarden. Replaced with per-session clones of a clean seed.

2. **Golden profile (playwright_profile_golden)** - Because the Bitwarden extension is loaded unpacked (from a folder), it gets a different ID (`hcgcgmick...`) than the web-store version (`nngceckb...`). Your original login lived under the web?store ID, invisible to the loaded extension. Fix: log in **once** into the folder-loaded version; capture that as the golden profile. Now the vault lives under the ID the extension actually uses.

3. **Seed profile (playwright_profile_seed)** - A stripped-down copy of the golden profile (small, fast to clone). Includes:
   - `Default/Local Extension Settings/hcgcgmick...` - the actual 4?MB vault with your account.
   - `Default/Preferences` and `Default/Secure Preferences` - **critical**. Without these, Chrome thinks the extension is a fresh install, and Bitwarden **wipes its own vault** on first launch (that was the second hidden bug). With Preferences included, the clone keeps the vault.

4. **New launcher (pw_mcp_launch.py)** - Every session clones the seed into its own temp directory, opens Chromium with `--user-data-dir` pointing there, and cleans up on exit. No shared lock, no lag - unlimited independent copies.

5. **No app restart required** - Existing running sessions keep their old browsers (most don't need Bitwarden). **Every new session automatically gets the fixed Bitwarden.** For any task that needs Bitwarden, just open a fresh chat.

## GOTCHAS & DEAD ENDS (rules to never repeat)

- **Do not use a single?profile lock or `--isolated`** - that guarantees logged?out browsers for all but one session.
- **Without `Preferences` files in the clone, the vault is wiped.** Chrome treats the extension as a fresh install, and Bitwarden clears its storage on install. Always include `Default/Preferences` and `Default/Secure Preferences`.
- **Extension ID mismatch** - web?store vs. unpacked extension IDs are different. The logged?in vault must be under the unpacked ID (`hcgcgmick`), not the web?store one. Any fix that only copies the old vault without this will silently fail.
- **Do not restart the desktop app to fix Bitwarden** - it would disconnect all running sessions from the board and make them unwakeable. Just open a new chat; the fix is already active there.
- **The seed is machine?specific** - `Preferences` tie the extension state to the machine. For other machines, you must rebuild the seed from a local golden login.
- **Bitwarden popup in headless mode might hang** - if testing, prefer headed mode or read storage directly (the `bw_storage_check.py` script).
