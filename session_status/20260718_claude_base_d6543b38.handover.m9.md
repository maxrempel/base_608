## DECISIONS MADE + WHY

### The Great Crash Hunt (SOLVED)
- **Symptom:** All buttons died after ~1 hour. Hard crash: `_ctypes.pyd 0x91bd` (access violation). No Python error - process just vanished. Restart didn't help because the bug was in the code.
- **Root cause:** COM interface calls. Two culprits removed entirely:
  1. **pycaw** reading Windows master volume for chime ? replaced with fixed level (0.35 scalar).
  2. **SoundCard** (WASAPI playback for multi-speaker chime fanout) ? replaced with `winsound.PlaySound` (pure Win32, zero COM).
- **Result:** Confirmed fixed - ~2 days uptime with zero crashes after removing all COM. The chime now plays on default device only, at a quiet fixed level. Max approved the trade-off.

### Language Auto-Detection (THE ACTIVE PROBLEM)
- **Problem:** OpenAI's built-in `language=auto` picks from ~99 languages. Max's accented short English clips get guessed as Finnish, Bulgarian, or Russian ? garbage output.
- **Attempt 1 (local clamped):** Use faster-whisper large-v3 to detect language, but clamp choice to RU vs EN only. Worked but slow (cold-start ~15s).
- **Attempt 2 (race + auto):** Fire local + OpenAI in parallel, pick fastest. Caused instability, was reverted.
- **Attempt 3 (OpenAI auto-detect, no forcing):** Let OpenAI decide. Worked better but still drifted to random languages on accented clips.
- **Final solution ("clamped auto"):** Run OpenAI **twice in parallel** - once forced as Russian, once forced as English. Compare `avg_logprob` (confidence) from each. Pick whichever is more confident. **Only RU vs EN - nothing else exists.** Applied to Num+/F9.
- **Bias added:** 0.15 margin favoring English. Why: Max's mistakes only ever go English?Russian (his accent makes English sound Russian-ish). The bias prevents near-tie coin-flips from flipping English to Russian. This is a **hand-tuned heuristic, not statistically calibrated** - pending proper calibration from real data.

### NumLock Independence
- Max keeps NumLock **OFF** permanently (nav mode) because he uses Home/End/PgUp/PgDn (numpad 7/1/9/3).
- NumLocker was unreliable and was disabled (autostart shortcut renamed to `.disabled`).
- Typer's numpad buttons (2/4/6/8/0) now bind to **numpad nav codes** (Down/Left/Right/Up/Insert) filtered by the **non-extended** flag - so real arrow keys (extended) pass through untouched.
- Result: numpad dictation works regardless of NumLock state. Real arrows still work.

### Safe Restart (NEVER interrupt Max)
- Built `restart_typer_safe.py` - waits for **40 seconds** of dictation-idle before touching anything.
- Shows a tiny amber toast in the corner: "typer updating..." - no full-screen flash, no focus steal.
- Branches: if buttons are DEAD ? restart immediately. If ALIVE ? wait for 40s idle then restart.
- This is now the **only** way to deploy typer changes. Enforced in `global2.md` rules.
- **Lesson learned (hard):** Max was furious when a forced restart cut his dictation. Never again.

### Mic-Following + Pre-Roll
- **Problem:** Mic was stuck on startup default. Re-initializing at press-time wiped the 2-second pre-roll buffer ? opening words truncated.
- **Max's fix:** Refresh the mic device **right AFTER each recording ends**, during his natural pause. The pre-roll buffer refills before the next press.
- **Warm-up indicator:** When mic isn't capturing yet (brief gap), the meter bar shows a **bright yellow dashed pattern** with "mic warming - wait" so Max knows not to talk.
- Result: mic follows Windows default, no truncated openings, visual cue for warm-up.

### Hallucination Cleanup
- Whisper hallucinates subtitle endings from training data. Added post-processing to strip:
  - **From end of text:** "??????????? ???????...", "??????? ?? ????????", "???????? ??????...", "thanks for watching", "subscribe..."
  - **If entire recording is just one word:** "???????", "you", "thank you" ? empty string.
- Regex-based, case-insensitive, handles ellipsis variants. Tested on Max's real clips.

### Chime Volume
- Reduced to ~half (fixed scalar 0.35, no COM). Max asked for quieter. Plays on default device only via winsound.
