The hook `block_death_spiral.py` false-blocks legitimate genomics work on the remote host `asto`. The root cause: it fingerprints commands by their outer shape only - specifically `ssh asto ...` - so three genuinely different piped scripts (recon, diagnose, launch) all read as "same command fired 3 times" and get blocked. Specific failures:

3. **Counts blocked attempts toward the counter** - a command that gets blocked still poisons the window, so the next genuinely different command has even less chance of passing.
4. **Foreground `sleep` block fires on one-shot `sleep N; check` patterns** - a legitimate pattern gets caught by the anti-loop logic.

**X10A already logged this** in `rule_inconsistencies_tomemex.md` on 2026-07-03.

**X10A's requested fixes (ranked):**
1. Exempt `run_in_background` calls entirely from the death-spiral hook

3. Don't increment the counter for blocked attempts
4. Treat `ssh host bash -s < differentfile` as distinct calls
5. Fix the foreground-sleep false-positive (one-shot sleeps should pass)
