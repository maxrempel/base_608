## DECISIONS MADE + WHY

1. **No existing tool was good enough.**  
   ? Zemail - unproven, zero user reviews, local-only, sends all mail through their API.  
   ? Context Link - brand new, solo dev, shaped as a "share a doc" tool, not built for 500k emails.  
   ? ragmail - required Rust + `just`, heavy Windows setup, 25-hour local ingest, no phone reach.  
   ? So we built our own, starting from the lightweight open-source `semantic-mail` and extending it heavily.

2. **Embeddings: OpenAI `text-embedding-3-small`.**  
   Cheap (a few dollars for the whole mailbox), no need to run a local model, privacy wasn't a concern - only account safety mattered.

3. **Read-only Gmail API - account-safe.**  
   Google OAuth with `gmail.readonly` scope. No scraping, no password IMAP. Google won't close the account for this.

4. **Index goes to Cloudflare Vectorize, not local ChromaDB.**  
   Needed to reach Claude on Android / web / Claude Code. A hosted index (Cloudflare) with a remote MCP Worker was the only architecture that works everywhere. The index is named `max-emails`, separate from Memex's `claude-memory`/`babel` - so Gmail junk never mixes with Memex.

5. **Archive (complete .eml files + attachments) goes to teal16.**  
   Pine's C: drive only has 476 GB (and ~13-15 GB free) - far too small for a 505k-email archive with attachments (potentially hundreds of GB). Centauri D: (teal16, 12.8 TB free) is the right home.

6. **Pipeline runs on asto (Liz's always-on Debian box), NOT Pine.**  
   Pine is a laptop that sleeps; the pipeline would pause for hours. asto is always-on, doesn't sleep, and has 985 GB free for staging. Pine stages one month, ships it to teal16, and deletes local files - never fills up.

7. **Attachment handling: PDF/DOCX text indexed, images saved but not indexed.**  
   The custom worker `archive_index.py` extracts text from PDFs (via `pypdf`) and DOCX (via `python-docx`), appends it to the email body for embedding. Images are saved as files but not fed to the embedding model.

8. **The remote MCP Worker solves the Android/web requirement.**  
   A Cloudflare Worker (`gmail-mcp-search`) binds to the `max-emails` Vectorize index, embeds the user's query with OpenAI, queries the index, and returns results in MCP format. Max adds the Worker's URL once in claude.ai Settings ? Connectors, and it auto-syncs to the Android app.
