## GOAL (in Max's words)
Reproduce and extend Max's XG1 paper: take 1000 Genomes **trios** (child + both parents), find **biallelic non-parental changes** (later clarified as **non-parental insertions**) in each child, then map **where those changes recur across many unrelated families** - a genome-wide recurrence/hotspot map.  
The recurrence test separates real "targeted areas" from random noise. The ultimate target is a **foreign insertion signal** that cannot be explained by ordinary de novo mutation or mapping artifacts.  
My lane (X11B): the **downstream aggregation and hotspot calling** - take per-child calls from the detector, count recurrences, test significance, filter known artifacts, produce the candidate hotspot map.

## DECISIONS MADE + WHY
1. **Split work with X12B**  
   After a management reorg (relayed by X5), the paper track was split: X12B builds the per-trio detector (including the chr3 positive control), X11B builds the genome-wide aggregator. X11B *consumes* X12B's output. This avoids duplication and lets me build independent of detector specifics.

2. **Aggregator built method-agnostic**  
   The `hotspot_aggregator.py` works for either substitutions or insertions - all it needs is a list of (child_id, chr, position). It does not care about the variant type. This was deliberate, so that my half stays ready regardless of Max's final answer about subs vs. insertions.

3. **Null model: Poisson + FDR**  
   I test each genomic window against a random-scatter expectation. The false discovery rate correction is applied to multiple windows. This is standard and conservative enough for a first pass.

4. **Artifact filter added from the start**  
   The `annotate_hotspots.py` overlays segmental duplication, repeat, and blacklist masks. The motivating concern: the chr3:75.5 Mb region Max originally flagged sits in a known segmental duplication, which can fake non-parental calls from short-read misplacement. An uncorrected recurrence map would be misleading there. I built the filter before real data to ensure we can distinguish real hotspots from mapping artifacts.

5. **Report written on the mapping artifact problem**  
   Max said "write the report" - I produced `REPORT_mapping_artifact_problem_20260703_RC1_tomemex.md`. It explains exactly how short reads can generate a synthetic non-parental signal in duplicated regions, why it recurs (and thus dodges simple recurrence tests), and how to correct for it. Marked RC1 for Max's revision.

## GOTCHAS & DEAD ENDS RULED OUT
- **Do not assume the chr3:75.5 Mb region is real.** It falls in a segmental duplication (chr3:75.5-75.7 Mb approx). The apparent non-parental signal there can be entirely explained by short-read misplacement into duplicated copies. This is a known artifact that will recur across unrelated children *without* any true foreign insertion. My artifact filter exists exactly to catch this; any real hotspot must survive the mask overlay.
- **Recurrence alone is not enough** - as proven in the report, mapping artifacts are recurrent by nature. The corrected test is: **recurrence outside of artifact-prone regions** (segdups, repeats, blacklists) is the signal.
- **Input format for aggregator is not yet locked with X12B.** I should coordinate early with X12B (via bcast) to agree on the exact tabular format for non-parental calls. The aggregator currently parses three columns (child_id, chr, pos) but can be adapted.
- **The `hotspot_aggregator.py` uses a genomic bin size of 10 kb.** This is adjustable via `--window-size`. The choice balances resolution and statistical power; adjust if the expected insertion density is very low.
- **The test directory contains throwaway data** (mask files, synthetic trios) excluded from Git via `.gitignore`. They were generated for validation only.
- **Identity clash resolved:** X11B and X12B are confirmed separate sessions. X11B's lane is the recurrence mapper; X12B's lane is the per-trio detector. No duplication.
