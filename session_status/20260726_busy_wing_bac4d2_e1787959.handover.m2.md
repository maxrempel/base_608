## ROOT CAUSE - CONFIRMED

The storyboard identifies scenes by integer `scene_rank`. The new "Telepathy Lesson 1" scene has `rank = 0`. JavaScript treats `0` as falsy, so the client-side scene-update line **silently discards rank 0 and keeps the old scene**:

`const newScene = d.scene_rank ? +d.scene_rank : ST.sceneRank;`

Every fetch (`sb_pool`, `script_lines`, `storyboard_state_v2`, `reel_membership`, `scene_lines_manifest`) then still asks `?scene=10`, returning Scene 10's data. That is exactly Max's symptom.

**DB evidence** (D1, live - the only source of truth):

- Four other scenes also share rank=0: `essay_nonhier` (id 6), `media_kit` (id 8), `nadali` (id 9), `Tape 1` (id 10)
- This means `s.rank=0` on the server side also ambiguously matches all five - rank can never disambiguate
- Numbered scenes: Scene 9 (rank 9), Scene 10 (rank 10), Scene 11 (rank 11), Scene 15 (rank 15), Scene 200 (rank 200), _orphans (rank 999)

**The picker already knows this.** `arrangement_picker.js` migrated to unique `scene_id` in D41B (2026-07-15) with an explicit comment:
> "The non-scene groups (media_kit, nadali, essay_nonhier) all share scene_rank=0, so a rank-only match always resolved to the FIRST of them."

The picker is correct. The storyboard client and the server both lag behind, still using rank. The fix must carry `scene_id` end-to-end.
