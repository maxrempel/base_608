## DECISIONS MADE + WHY

### Naming: "Active" not "Done"
Max suggested "Done" for the merged button. I chose **"Active"** because most items under it are NOT done - they're in flight (pending, queued, running, submitted). "Done" would be misleading when the grid shows items still rendering. Max authorized minor choices; this was one.

### The set `active` covers
`['pending', 'queued', 'running', 'submitted', 'done']` - everything except the human verdicts (approved/junk) and terminal problems (error/held/missing). "submitted" is included here even though no worker actually writes that status string - it's a dead legacy value, harmless to include, and the merge makes it vanish from the UI anyway.

### Poll target: `/api/stats`, not `/api/jobs`
`/api/stats` runs cheap GROUP BY COUNT queries against D1 (Cloudflare D1 is the live DB). `/api/jobs` is heavy (~1-2s). The poll fetches only stats, diffs a mode-scoped JSON signature, and calls the expensive `loadAll()` only when something actually changed. This directly avoids the known D30recoder 2s-blink bug where unconditional `loadAll()` caused page flicker.

### Poll lifecycle
- Starts when `loadAll()` detects `RENDERING_STATUSES > 0` in stats for the current mode, OR immediately after a fire (`onPromptSubmitted`).
- Every 3s: fetch `/api/stats`, compute signature, if changed ? call `loadAll()`, if `RENDERING_STATUSES.count === 0` ? **self-stop**.
- 30-minute hard cap timeout (paranoid safety valve so it never runs forever on stale DB rows).
- Only one poll interval at a time (guarded by `window._smartPoll`).

### Image stats group added to `get_stats()`
The imager tab had no stats group - `get_stats()` only returned photo/video/lipsie. Added `"image": {status: count, ...}` for job_type='image' rows so the smart poll has something to diff in the imager.

### localStorage migration
Old persisted filter values like `'done'`, `'queued'` etc. are auto-migrated to `'active'` on page load so the new button highlights correctly even for returning visitors.

### Version bump
APP_VERSION is git-derived (`_auto_version()` reads commit count + last code commit hash). The commit message IS the version. No manual bump needed - the commit handles it.

## GOTCHAS + DEAD ENDS

- **Edits go to main checkout, not worktree.** The main checkout (`C:\moma\`) is on master and is what the running servers serve. Edits made directly there - no need to copy. Just commit from the main checkout.
- **combo_gui.py has an auto-restart watcher** - it watches combo_gui.py, runner.html, moma_db.py, paths.py. It does NOT watch runner_core.js (static file). After editing runner_core.js, a browser hard-refresh is sufficient to pick up the new JS.
- **`setInterval` inside the smart poll must be `async function`** - the API call inside needs `await api('/api/stats')`. A plain function would swallow the promise.
- **30-minute timeout on the smart poll** - implemented as a paranoid guard against stale DB rows (e.g. pending jobs that will never resolve) keeping the poll alive forever.
- **"submitted" is a dead status** - no worker writes it. The reel worker (combo_wan26au_worker.py) keeps the job at `queued`/`running` through the DashScope submit+poll cycle, then flips to `done`. The filter button existed but matched zero rows. Including it in the "active" set is harmless and makes the merge clean.
- **Suicide-prevention hook** blocks 2+ consecutive Reads of the same file with no intervening tool call. Grep or Edit between Reads to avoid it.
- **Playwright browser lock** - only one session can hold the Playwright browser at a time. Always close it when done. (It was closed at the end of D41.)
- **D30recoder's 2s blink bug** - unconditional `loadAll()` every 2s causes page flicker. This is the precedent that informed the "decouple poll from render" spec. The smart poll's signature-diffing is the direct countermeasure.
