3. **Auto-derive membership map from D1 (not a hand-edited file).** The old hand-maintained `reel_membership_sc10.json` was the source of the endless "spot goes blank" bugs. New endpoint `/api/reel_membership_sc10` (in `slideshow_server_v01.py`, v2.36) derives every reel's member-line-indices live from three sources: (a) `line_hash` matches a script line ? single-line, (b) `vocal_line` contains `[3, 4]` index markers, (c) D21's seed file as fallback. **Critical bug I fixed:** D1ConnectionProxy returns rows as **dicts** (not tuples). My initial v2.36 used `r[0]` tuple access and silently returned `{}` ? every spot went empty. Fixed in `cdeab42` by switching to `r['line_hash']`.

4. **Strict exact-match filter; no pins.** Per Max: "all there shouldn't be pinning, and if any clip is not fitting, it probably doesn't work." The storyboard v2 filter now:
   - Merged spot ? reel's member-set must equal spot's line-set exactly (CSV match).
   - Single-line spot ? reel must cover that single line.
   - No UNKNOWN tolerance (my v2.32 bandage removed in v2.36).
   - Slot-pick is **deterministic**: newest job_id among matching reels wins. No pins consulted.
   - **Image fallback** (v2.38): if no lipsie matches, fall back to the image/clip the user manually dragged onto the spot.

5. **Spine 1 ? 2 swap is preference, not pinning.** v2.39: `ST.assigned` means "my preferred 1st-spine pick" but **only if the reel already passes the filter.** Drag 1st?2nd demotes the preference and auto-picks the next-newest matching reel. Drag 2nd?1st promotes. No pins are created, deleted, or stored in D1 by these drags.

6. **mixboard (player) also uses membership map.** v50: The per-line picker in mixboard.html loads `/api/reel_membership_sc10` so merged reels like J2845 (covering idx 17-22) appear as candidates for every covered line. Without this, the player jumped to obsolete single-line reels after line 16.

## GOTCHAS

1. **D1ConnectionProxy returns dicts, not tuples.** Any new code querying D1 in slideshow_server or combo_gui must use `row['column_name']`, never `row[0]`. My v2.36 shipped with this bug and silently returned empty membership ? every spot blank.

2. **Browser cache is the silent killer.** No-cache headers are ignored. The storyboard v2's JS is **inline in the HTML page**, so it can't use `?v=mtime`. Always tell Max to **hard-refresh (Ctrl+Shift+R)**. The bulletproof fix (extract JS to external `?v=mtime` file) hasn't been done - it's the same approach combo_gui uses.
