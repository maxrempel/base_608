3. **Upload via Odysee's web API (tus resumable upload + asynqueries publish).** Reverse-engineered by doing one real test upload through the browser while logging network calls. Flow: auth_token ? mint tus JWT via `asynqueries/uploads/` ? tus POST upload bytes ? `stream_create` publish via `asynqueries/` with channel_id + wallet signing server-side. No local lbrynet daemon needed.

4. **Throttle baked INTO the uploader (not OS-level QoS).** The original OS-level `New-NetQosPolicy` cap was bound to OdyseeSync.exe (now retiring). Replaced with a token-bucket limiter inside the Python uploader - it re-reads capacity from the state file every chunk, so it can't be mis-pointed or bypassed. Recalibration now every 4 hours (Max: "every four hours, recalibrate now").

5. **Auth via Bitwarden ? 6. **No-title files: SKIP, don't publish with ugly id-titles.** 20 of the 292 missing videos had no title in the June inventory, and the .mkv files carry no embedded title metadata (yt-dlp didn't set it). Rather than publish `--rL16qPIuQ` as a title, they're deferred to a `needs_title.txt` list. The 272 properly-titled ones upload now.

7. **Schedule: hourly task `OdyseeUpload` runs `run_odysee_upload.bat`.** The uploader is resumable - it checks Odysee before each upload (no-dup guard) and writes a ledger of claimed IDs. Survives reboots, picks up where it left off.

## GOTCHAS / DEAD ENDS

1. **Do NOT use OS-level QoS anymore.** The original `New-NetQosPolicy -Name OdyseeThrottle` is still on Centauri, bound to `OdyseeSync.exe`. It's irrelevant now. The real throttle is the token-bucket inside `odysee_upload.py`.

2. **Do NOT try feed-local with OdyseeSync.exe.** The tool cleans up after upload, has no local-file slot, and the workdir is a wasteland. That path is dead.

3. **UTF-8 BOM on state file.** PowerShell's `Set-Content` prepends a UTF-8 BOM. The uploader was patched to use `io.open(..., encoding="utf-8-sig")` to handle it. If you rewrite the state file, don't break this.

4. **No embedded title in .mkv files.** yt-dlp did not embed title metadata. The fallback to ffprobe was tested and returned nothing. Don't waste time on it - the 20 no-title files need an external source.

5. **PowerShell test harness mangles UTF-8.** Running the uploader through a PS wrapper (especially with here-strings or Get-Content) corrupts Cyrillic titles. Use the .bat file directly, or set `PYTHONUTF8=1` and use Python-native IO.

6. **SSH remote shell defaults to cmd.exe.** Always invoke `powershell -NoProfile -ExecutionPolicy Bypass -Command` or pipe a .ps1 heredoc. Single-quoted heredocs prevent bash from eating `$_` and backslashes.

7. **OdyseeSync.exe stalled around June 5.** It holds 11 staged .zip bundles (~15 GB) from April-June but hasn't uploaded anything since. It's alive (CPU time accumulating) but not actually publishing. The cause was never diagnosed - and doesn't matter now since we're retiring it.

8. **OdyseeSync.exe talks only to Cloudflare 443.** No local lbrynet, no local wallet. The app uses Odysee's server-side wallet with an auth token. Our uploader does the same.

9. **Hook rate-limits repeated scp commands.** If deploying files repeatedly fails, push via stdin (`Set-Content` via SSH) or combine multiple operations into one script.

10. **The `_defer:true` pattern in asynqueries.** The first `stream_create` call with `_defer:true` is a cost preview - the real publish is the second call without it. Our uploader does both.
